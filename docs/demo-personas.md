## Enable a real demo

Use the Supabase SQL editor or a server-role admin system to configure a demo. Ordinary users cannot write shared demos, trials or analytics. Set face_asset_reference to a worker-resolvable licensed model/asset ID; configure the worker to resolve this reference independently of user-owned persona preparation. Remove metadata.placeholder (or set false), set face_ready and inference_ready only after validating real transformed output. Set voice_asset_reference and voice_ready only for a working synthetic or licensed voice. Keep ownership/license evidence in metadata. Inactive records disappear from the cached library within 60 seconds; the session API always checks current DB activation/readiness and never relies on cached UI readiness. Administrators can add, disable, reorder, feature or edit records in one table without touching components.

The common inference session payload includes persona_id (the demo UUID) and optional identity: {kind:'demo',face_asset_reference,voice_asset_reference}. Only the server sends these references to the worker; browser library metadata does not include them. Local and remote workers use the same interface. A demo without voice uses normal microphone input and forces voice conversion off.

## Trial behavior

The original application had monthly streaming-minute quotas, **no existing 60-second trial**. This migration adds a one-time account-wide demo trial. Reservation locks the account row, verifies readiness and uses the unique active-session/trial constraints. Concurrent starts cannot claim multiple trials. Setup failures release the trial reservation; a successfully connected session consumes it. Every demo session has a 60-second cap and watermark; High Quality is unavailable in the trial. The worker must enforce max_duration_seconds=60 and revoke publisher/viewer connections on stop. Client/server polling is a reconciliation mechanism and does not replace worker enforcement. Trial usage is separate from the monthly minute allowance. Completion records once via finish_session, with analytics keyed by session/event.

Preview-only demos can be preselected in Studio for exploring raw camera input. Start Trial is disabled and the API rejects bypass attempts. No uploads are needed to use an administrator-configured ready demo. The seed alone cannot supply live transformation. Paid checkout and monetary credits remain outside the existing implementation; no fake purchase or conversion is emitted.

## Analytics

Views/selections/custom-persona clicks are bounded, asynchronously batched; analytics failures never block Studio. Started/completed events are emitted by the server/atomic completion procedure. `demo_to_paid_conversion` is reserved for a verified payment webhook, **not a client click**. The app has no payment provider yet. A future payment integration should insert this event only after confirmed purchase, with a durable provider-event idempotency key. Browser clients cannot submit started/completed/paid events or another user's identifier.

## Performance changes and checks

Concrete source bottlenecks addressed: session-recovery busy state gated safe camera controls; capture completion created identical replacement streams; camera switches unmounted the video element; thumbnails were signed serially; diagnostics state rerendered the entire Studio; repeated concurrent GETs were not deduplicated; intervals could overlap slow requests. Camera input uses the browser video element, no frame/audio buffers in React state. Capture defaults remain 1280�720, at most 30 FPS. Browser-local preferences restore independently of AI. Advanced controls, development diagnostics and OBS instructions are loaded only when needed. Shared demo metadata is cached for 60 seconds; only visible grid thumbnails and selected persona imagery load. The library publishes six finished avatar bundles; larger admin catalogs progressively reveal 12 cards at a time. Server auth reads are deduplicated per React request.

Run `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:media`, and `npm run test:studio`. Studio profiling uses the actual component with synthetic browser devices and a deliberately delayed session-recovery API; only Next Image/Link/dynamic wrappers are substituted for the standalone fixture. It records React Profiler commits, Chrome CPU samples, long tasks, actual video frames, stream attachments, request counts, selection/switch behavior and unmount cleanup. Results/screenshots/CPU profile are written under test-results. This checks regressions without Supabase but is not a substitute for authenticated browser ? API ? database verification or real-device latency measurements.

Development diagnostics update locally at 1 Hz: raw preview FPS, resolution, dropped frames, Studio render count, API timing, worker-reported latency and inference connection time. True end-to-end latency requires timestamp instrumentation in the worker; it is never invented from request duration. Production users do not receive developer diagnostics.
